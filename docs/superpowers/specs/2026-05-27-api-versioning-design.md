# API Versioning Design

**Date:** 2026-05-27  
**Branch:** feature/versionning  
**Status:** Approved

---

## Context

The Doggo backend (AdonisJS V7) currently exposes routes without any version prefix (`/dogs`, `/users`, etc.). This design introduces URL-based versioning to support breaking changes cleanly across 7 modules, with granularity down to the individual route level.

---

## Goals

- All existing routes migrated to `/api/v1/...`
- Support future `/api/v2/...` routes coexisting with v1
- Per-module and per-route versioning granularity
- Single Swagger doc (no per-version split)

---

## Approach: Central version group in `start/routes.ts`

`start/routes.ts` is the single source of truth for which modules are on which version. Each module exposes versioned route files (`routes.v1.ts`, `routes.v2.ts`). The central file wraps them in `router.group().prefix('/api/vX')` groups.

This gives a global view of versions without scattering version logic across modules.

---

## File Structure

### Per module

Each module renames `routes.ts` to `routes.v1.ts`. Future v2 changes add a `routes.v2.ts` alongside it.

```
app/modules/{module}/infrastructure/http/
  routes.v1.ts     ← current routes.ts renamed
  routes.v2.ts     ← added per module when needed (future)
```

### Module route files

Module route files are unchanged in logic. They keep their resource prefix but drop any version prefix (handled by the central group).

```typescript
// dogs/routes.v1.ts
router
  .group(() => {
    router.get('/', [IndexRobotDogController])
    router.get('/users/:id', [ListUserRobotDogsController])
    router.get('/:id', [ShowRobotDogController])
    router.post('/', [CreateRobotDogController])
    router.delete('/:id', [DestroyRobotDogController])
    router.put('/:id', [UpdateRobotDogController])
  })
  .prefix('/dogs')
  .use(middleware.firebaseAuth())
```

### `start/routes.ts`

```typescript
import transmit from '@adonisjs/transmit/services/main'
import { middleware } from '#start/kernel'
import router from '@adonisjs/core/services/router'

transmit.registerRoutes((route) => {
  if (
    route.getPattern() === '__transmit/subscribe' ||
    route.getPattern() === '__transmit/unsubscribe'
  ) {
    route.middleware(middleware.firebaseAuth())
  }
})

import './routes/swagger.js'

router.group(() => {
  import('../app/modules/auth/infrastructure/http/routes.v1.js')
  import('../app/modules/users/infrastructure/http/routes.v1.js')
  import('../app/modules/dogs/infrastructure/http/routes.v1.js')
  import('../app/modules/missions/infrastructure/http/routes.v1.js')
  import('../app/modules/actions/infrastructure/http/routes.v1.js')
}).prefix('/api/v1')
```

Transmit routes (`__transmit/...`) stay outside the versioned group — they are not part of the versioned API.

---

## Per-route versioning pattern

When a single route changes in v2:

1. Create `routes.v2.ts` in the module with **only the changed route(s)**
2. In `start/routes.ts`, add a v2 group that imports v2 overrides first, then v1 as fallback

```typescript
// start/routes.ts
router.group(() => {
  import('../app/modules/dogs/infrastructure/http/routes.v2.js') // override first
  import('../app/modules/dogs/infrastructure/http/routes.v1.js') // fallback for unchanged routes
}).prefix('/api/v2')
```

AdonisJS matches routes in registration order — v2 routes take precedence, v1 fills the rest.

When a full module changes to v2, import only `routes.v2.ts` (no fallback needed).

---

## Swagger

`adonis-autoswagger` uses `tagIndex` to group routes by URL segment.

| Before | After |
|--------|-------|
| `/dogs` → `tagIndex: 2` → tag `dogs` | `/api/v1/dogs` → `tagIndex: 3` → tag `dogs` |

**Change:** `config/swagger.ts` → `tagIndex: 2` → `tagIndex: 3`

Routes `/swagger.json` and `/docs` remain outside the versioned group (no `/api/v1` prefix).

## Types

`.adonisjs/server/routes.d.ts` is auto-generated by `node ace generate:types`. It updates automatically after migration — no manual action required.

## Future convention

When adding v2 for a module or route:

1. Create `routes.v2.ts` in the module
2. Add a `router.group().prefix('/api/v2')` block in `start/routes.ts`
3. For partial v2: import v2 first, then v1 as fallback in the group
4. For full module v2: import only v2
